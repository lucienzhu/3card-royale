```python
import numpy as np
from threecard_royale.gym_env import RoyaleEnv

env = RoyaleEnv(episode='match', player=0, render_mode='ansi')
obs, info = env.reset(seed=42)
rng = np.random.default_rng(42)
done = info["reset_terminal"] or info["reset_truncated"]
while not done:
    # Replace masked random sampling with a trainable policy.
    action = int(rng.choice(np.flatnonzero(obs['action_mask'])))
    obs, reward, terminated, truncated, info = env.step(action)
    done = terminated or truncated
env.close()
```

`gym.make('ThreeCardRoyale-v0')` is registered after importing `threecard_royale.gym_env`. `RoyaleEnv` follows Gymnasium's reset/step API and supports `SyncVectorEnv`. The model reproduction was verified with Gymnasium 1.4.0; the optional dependency range is >=1.2,<2.

## Task and reward

- `episode='game'` ends on the next small-game win/loss; default.
- `episode='match'` automatically advances small games and ends on the race-to-A winner.
- Terminal reward is +1/-1 from the learner's perspective. Nonterminal legal decisions give 0; no damage or level reward shaping is hidden in the default task.
- Invalid indices give -0.05 without changing game/RNG; they count toward `max_steps`. Use the mask. Step after termination/truncation requires reset.
- `max_steps=4096` bounds learner decisions; `max_internal_steps=10000` also bounds automatic/opponent transitions. Time-limit endings set `truncated=True`, not a fake win. Reset info flags the unusual case of a reset reaching a bound/terminal before a decision.

Reset options are `first:0|1` and `levels:[2..14,2..14]`; nonstandard levels are explicit training starts, not a new real-game setup rule. The core seed is generated by the environment's seeded NumPy generator. It is not returned to the policy.

## Observation and action contract

`Discrete(512)` actions are **indices into the current candidate table**, not globally fixed card combinations. Do not cache an index across steps. Alive players have at most 12 usable cards; the 512 capacity covers all current-rule plays and swap routes. Unused candidate rows are zero, with mask 0.

| Key | Shape / dtype | Contents |
| --- | --- | --- |
| `cards` | 6×52 / int8 | Own hand, own wounds, rival public wounds, public discard, own active play, rival active play |
| `meta` | 24 / float32 | Phase one-hot 0..5; own/rival level, flower, wounds, hand/deck/discard counts, A lights, first/attacker, battle index, remaining swaps, acting flag, capped round/game progress, task flag |
| `candidates` | 512×72 / float32 | Current action features, detailed below |
| `action_mask` | 512 / int8 | 1 exactly where an action is legal |

Candidate columns 0..51 mark cards used/given. Columns 52..56 one-hot play/swap/decline/advance/next-game; 57..58 source hand/wounds; 59 source index/11 for swaps; 60..63 deck/blind/own-zone/rival-zone; 64..66 known incoming rank/14, suit/3 and ID/51; 67 score/7, 68 type/7, 69 top comparison rank/14, 70 card count/5; 71 is 1 for a play when this player owns the current Ace challenge, otherwise 0. Unknown target identities are never encoded. Type IDs are high 0, pair 1, straight 2, flush 3, trips 4, straight flush 5, four of a kind 6, five of a kind 7. Their scores differ for trips/straight-flush; use score as the ranking.

Each swap opportunity can be used or skipped independently. Both `skip_swap` and `stop_swaps` set the decline-kind bit at column 54. For these actions, column 59 is a flag: 1 skips only the current opportunity; 0 ends all remaining opportunities. Skipping changes no cards or RNG. The candidate shape remains 512×72.

`env.action_masks()` returns a boolean mask for mask-aware algorithms. Candidate encodings let a policy associate dynamic indices with actual moves; an index alone has no stable meaning. Algorithms without masking need an explicit masked distribution/wrapper.

## Connecting a trainable policy

Flatten `cards` in row-major order and append `meta` to form the 336-value state.
Score each 72-value candidate with a shared network; mask padding before the
loss, sampling or argmax. The [released 256/128 policy](MODEL.md) provides matching
Torch, ONNX and browser inputs plus a runnable Gym inference example.

A Gym step includes the learner move, opponent decisions and automatic transitions
until the next learner decision or episode boundary. The task flag in `meta[23]`
is 0 for `game` and 1 for `match`; the released model was trained for `game`.
Handle `reset_terminal` / `reset_truncated` before sampling, including in vectorized
rollouts. [The RL extension plan](MODEL.md#extending-the-baseline-with-rl) covers
actor initialization, stored action tables, critic separation and evaluation.

## Opponents and self-play

Pass `opponent=callable(observation, legal_actions)`. The default is the simple visible-information heuristic. The callback gets detached player observations, not the Game object. Observations and info expose no opponent hand identities, deck order, RNG or seed. Full debug saves remain host-only.

For explicit two-agent self-play, use the turn-based `Game` API, query `actor`, and pass that player's observation to their policy; the host executes `advance` / `next_game` transitions. The trained BC policy is described in [Model](MODEL.md); a PettingZoo adapter and reward-trained RL trainer are not implemented. Keep the learner's replay buffer restricted to its own observation/action/reward sequence. A full-information critic, if added, should be an explicit separate training choice.

Run `python -m unittest discover -s tests -p 'test_*.py'` for the official Gym checker, hidden-state invariance, vectorization, masks, episode termination and time limits. Standard API design follows [Gymnasium's custom environment guide](https://gymnasium.farama.org/introduction/create_custom_env/).

Standard 1.0 adds five of a kind (7 points): four natural equal-rank cards plus the shared flower. See [complete standard rules](RULES.md). Five-card plays are included in legal actions. `wild.as` is a virtual face; in five of a kind it may name an already-present representative face without reusing a physical card. Gym score/kind features use /7 and played-card count uses /5.
