# 3Card Royale v1.0.0

Stable snapshot · 2026-10-25 · Standard Rules **1.0.0** · SDK **0.2.0**

[Play](https://lucienzhu.github.io/3card-royale/) · [Release](https://github.com/lucienzhu/3card-royale/releases/tag/v1.0.0) · [Audit data](v1.0.0-audit.json)

## Included

- Easy uses up to **64** candidate plays; Medium uses the committed **256 → 128** neural policy; Hard uses the original browser Code AI. Hard can swap a rival's private hand blindly, as well as public wounds.
- Replay animations run inside the replay dialog, with correct coordinates, cancellation and public/private card treatment. Motion respects the player's setting and reduced-motion preference.
- The four native GameCore implementations, Gym environment, bilingual rules, design system, sharing components, model and reproduction materials are fixed at this tag.
- Chinese and English blog references are pinned to this tag. The personal website release tag is `3card-royale-v1.0.0`; this release changes only Royale articles and citations. A separate concurrent website redesign had already reached the remote; its published tree is preserved.

This release freezes the existing gameplay, dealing rules and checkpoint. The final release commit adds audit records and synchronizes the Chinese replay-design documentation; it does not rebalance the opponents or shuffle algorithm.

## Frozen neural checkpoint

`models/nn-policy/policy-mlp-256-v1.onnx` · **552,407 bytes** · **137,729 parameters**

```text
SHA-256 5b98061d4188c116080eb6784c6378536a89e0b3c1db333df88217379e4dde13
336 observation + 72 candidate → 256 → 128 → 1
```

This is a behavior-cloning baseline trained on 10,000 SDK Code AI self-play games. The selected checkpoint is epoch 5. The recorded reproduction rebuilt both data and model byte for byte; see [reproduction record](../experiments/nn-policy-v1/reproduction-256.json).

The original NN/SDK study remains **46.2%**. Against restored browser Hard, NN wins **41.2%**, Easy **31.5%**, and SDK Code AI **45.3%**, each over 1,000 games. These are different opponents and are not interchangeable. Easy wins **44.1%** against NN. No historical result has been relabeled.

The published **1.1 ms p95** for the deployed NN is the recorded Mac Chrome, single-threaded WASM result with 220 candidates; it is not a mobile or end-to-end turn measurement.

## Website scope and concurrent publication

The initial published legacy site had eight missing references and two broken
anchors on older unrelated pages, plus a slideshow initializer loaded before
jQuery. Before this release was submitted, another publication replaced that
site with the bilingual redesign at `88cd995928b88cb9d8ad2991e8915acf6efdc289`.
Its tree exactly matched the locally audited branch. The new published site's
build and link audit passed with no missing local targets or anchors.

This release was rebased onto that already-published tree. It adds only Royale
article release markers, frozen experiment links and figure provenance. It does
not publish, revert or overwrite the concurrent redesign or Tennis Robot copy.
The initial legacy findings remain in the JSON as a superseded audit, not
outstanding defects in the new published site.

## Repeat the checks

```sh
node scripts/check.cjs
python -m unittest discover -s tests -p 'test_*.py'
cd rust && cargo test --locked && cargo build --locked && cd ..
cmake -S cpp -B build/cpp -DCMAKE_BUILD_TYPE=Release
cmake --build build/cpp
ctest --test-dir build/cpp --output-on-failure
python tests/conformance.py --rust rust/target/debug/royale-json --cpp build/cpp/royale-json-cpp --report conformance.json
tsc --noEmit --strict --target ES2020 --module commonjs tests/types.ts
```

Use the dependencies and model reproduction instructions in [training/README.md](../../training/README.md). Run `training/parity.py` against the reproduced checkpoint directory. The site repository contains the figure generators and Jekyll sources.
